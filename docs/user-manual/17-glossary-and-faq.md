# Glossary of Enterprise Terms & Frequently Asked Questions

---

## 1. Enterprise SAP & Accounts Payable Glossary

| Term / Acronym | Definition & Context in SAP S/4HANA |
|---|---|
| **3-Way Match (LIV)** | Logistics Invoice Verification comparing Purchase Order (`EKKO`/`EKPO`), Goods Receipt (`MSEG`/`MATDOC`), and Supplier Invoice (`RBKP`). |
| **BELNR** | *Belegnummer* — The 10-digit primary financial accounting document number generated in SAP FI-AP upon financial posting (`MIRO`). |
| **BSAK** | SAP transparent table containing cleared vendor open items (*Buchhaltungsdaten: Sekundärindex für Kreditoren - Ausgeglichene Posten*). |
| **BSIK** | SAP transparent table containing open (unpaid) vendor items. |
| **Clean Core** | SAP architectural standard mandating zero modifications to standard SAP ABAP core tables, utilizing side-by-side BTP apps and public APIs. |
| **CP / CPI** | SAP Cloud Integration (formerly CPI) — Integration Suite middleware managing OData, SOAP, and IDoc message flows between cloud apps and ERP. |
| **EKKO / EKPO** | Standard SAP purchasing tables: `EKKO` stores Purchasing Document Header; `EKPO` stores Purchasing Document Line Items. |
| **F110** | SAP standard transaction code for the Automatic Payment Program (*Zahlprogramm*), executing bank disbursements and creating payment documents. |
| **GSTR-2B** | Static auto-drafted monthly statement generated by the Indian GST portal on the 14th of every month, reflecting inward supplies reported by vendors. |
| **IRN** | Invoice Reference Number — 64-character SHA-256 cryptographic hash generated by the government Invoice Registration Portal (IRP). |
| **ITC** | Input Tax Credit — Taxes paid on inward purchases that an enterprise can deduct from its outward tax liability under GST law. |
| **Joule** | SAP's contextual Business AI assistant integrated into SAP applications. |
| **LIV** | Logistics Invoice Verification — Sub-module within SAP Materials Management (MM) handling invoice reconciliation against POs and receipts. |
| **MATDOC / MSEG** | SAP material document tables: `MATDOC` (S/4HANA Universal Journal for Inventory) and `MSEG` (ECC/S4 compatibility view for Goods Receipts). |
| **MIRO** | Standard SAP transaction code used to enter incoming invoices and create permanent accounting documents in the general ledger. |
| **MIR7** | Standard SAP transaction code used to park incoming invoices as preliminary documents with payment block keys. |
| **Payment Block Key R** | Standard SAP payment block code indicating an invoice has been parked for Logistics Invoice Verification review and cannot be disbursed. |
| **QALS** | SAP transparent table storing Quality Management (QM) inspection lot master records. |
| **Tolerance Key PP** | Standard SAP tolerance rule governing unit price variance between the PO item and the invoice line item (standard threshold: ±5.0%). |
| **Tolerance Key DQ** | Standard SAP tolerance rule governing quantity variance and over-delivery against Goods Receipts (standard threshold: 0%). |
| **Tolerance Key BD** | Standard SAP tolerance rule permitting minor balance differences (small difference rounding). |

## 2. Frequently Asked Questions (FAQ)

### Q1: Does Invoice Decision Intelligence modify standard SAP S/4HANA tables directly?
**Answer**: No. In accordance with SAP Clean Core principles, the platform never modifies SAP tables directly. It is designed as a side-by-side cloud application running on SAP BTP that interacts exclusively through published, public SAP OData APIs (`API_SUPPLIERINVOICE_PROCESS_SRV`) or SAP Integration Suite message queues.

### Q2: Does the AI Decision Engine send invoice data to external public AI services?
**Answer**: No. All scoring, tolerance evaluation, Bayesian confidence calibration, and evidence classification are executed locally by deterministic enterprise rule engines in `AIDecisionEngine.ts`. This guarantees zero data leakage, zero reliance on external public cloud APIs, and 100% auditable results for financial compliance.

### Q3: How does the system prevent paying the same invoice twice?
**Answer**: The system applies three concentric layers of duplicate protection:
1. **Intake Screening**: Inward invoices are cross-referenced against the S/4HANA invoice index (`BSIS`/`BSAS`) matching supplier tax ID, invoice number, and currency (Scenario 7).
2. **AI Decision Block**: Duplicate suspects are immediately flagged with `HOLD` recommendation and `CRITICAL` risk.
3. **API Hard Stop**: The `SAPPostingService` enforces strict state checks; attempting to post an invoice already in `POSTED` status or flagged as a duplicate suspect is rejected by the backend.

### Q4: Can this application connect to our live SAP S/4HANA system?
**Answer**: Yes. The codebase implements the adapter pattern (`ISAPAdapter`). By toggling `DEMO_MODE=false` and configuring standard SAP BTP Destination credentials, the platform switches from `MockSAPAdapter` to `S4HanaCloudAdapter`, consuming live S/4HANA OData services.

### Q5: What happens when a Business Owner rejects an invoice?
**Answer**: Rejection requires a mandatory justification reason. Submitting a rejection sets the invoice status to `REJECTED`, updates the AI recommendation to `REJECT`, records the dispute in the immutable audit trail with actor name and timestamp, and permanently blocks any financial posting or payment in S/4HANA.

### Q6: How does the What-If Simulator help procurement teams?
**Answer**: The What-If Simulator allows procurement managers to interactively test how adjusting price tolerances, quantity buffers, or quality strictness impacts straight-through processing rates. It recalculates recommendations in real-time in memory without altering master system configuration or committing unauthorized postings.
